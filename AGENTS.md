# AGENTS.md — instructions for coding agents (OpenAI Codex / GPT, Claude Code, etc.)

This repository turns three INDOT bridge inspection reports (NBI data + inspection photos) into photoreal Blender/Cycles
models of the bridges, plus web-viewable GLB exports and renders. **Your job as a reviewing agent is to verify the models
against the source data**, and to fix the generator when something is wrong. Nothing here needs a GPU.

## Layout

```
bridges/<folder>/bridge.json        all dimensions used by the model, with the NBI item they came from (ground truth)
bridges/<folder>/report_text.txt    full text of the inspection report (pdftotext -layout) — the primary source
bridges/<folder>/photos/            inspection photos + index.json (report captions)
bridges/<folder>/renders/           Cycles renders of the model (1920x1080) named after the cameras in bridge_gen.py
bridges/<folder>/model/             bridge_<id>.glb (full) and bridge_<id>_lite.glb (gltfpack-compressed)
bridges/<folder>/verification/      pairs.json (render<->photo pairs), dimension_report.*, compare_*.jpg (generated)
blender/bridge_gen.py               parametric generator: BRIDGES dict (modelling assumptions) + build/render/export
blender/common.py                   mesh/material/vegetation/world helpers shared by all bridges
blender/tex/                        procedural textures (generated by blender/gen_textures.py)
tools/verify_model.py               dimensional checks of a GLB/blend against bridge.json (pure Python)
tools/compare_photos.py             builds render-vs-photo comparison sheets
tools/run_checks.sh                 runs everything above; non-zero exit on any FAIL
viewer/                             three.js viewer (GitHub Pages)
```

Bridge ids: `07620` (SR 28 over Little Wea Creek, 3-span RC slab on pile bents, 20° skew),
`41750` (I-70 EB over Bayliss State Ditch, 3-span RC slab on solid pier walls, 15° skew),
`19027` (WB Sagamore Pkwy / US 52 over 9th St + CSX + ramp, 6-span steel W36 multi-beam viaduct, 525 ft).

## Setup

```bash
python3 -m venv .venv && . .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt                        # bpy 5.2.x needs CPython 3.13; on 3.11 use bpy==4.2.*
python3 -c "import bpy; print(bpy.app.version_string)"
```
`tools/verify_model.py` and `tools/compare_photos.py` need only numpy + Pillow (no Blender).
If `bpy` cannot be installed, do the verification on the committed GLBs and renders and skip the rebuild steps.

## Commands

```bash
# 1. dimensional verification of the committed models (fast, no Blender)
python3 tools/verify_model.py --all                     # -> bridges/*/verification/dimension_report.md, exit 1 on FAIL
# 2. render-vs-photo sheets for visual review
python3 tools/compare_photos.py --all                   # -> bridges/*/verification/compare_sheet.jpg
# 3. rebuild a bridge from bridge.json + the BRIDGES entry (≈3 s) and check the .blend directly
cd blender && python3 bridge_gen.py --build 07620 && cd .. && python3 tools/verify_model.py 07620 --blend
# 4. quick look renders (960x540, 24 spl, ~25 s per view on 4 CPU cores); views listed in BRIDGES[id]['cameras']
cd blender && python3 bridge_gen.py --render 07620 preview elevation pier     # -> blender/out/07620/renders_preview/
# 5. final renders + exports (what is committed)
cd blender && python3 bridge_gen.py --render 07620 final && python3 bridge_gen.py --export 07620 && python3 bridge_gen.py --export 07620 --lite
# 6. everything, with exit status
bash tools/run_checks.sh
```

Coordinates are feet. X runs along the bridge in the direction of travel (station), Y is left, Z is up, the deck riding
surface is Z = 0. Skewed support lines run along (sin s, cos s). Node/object names are stable and are what
`verify_model.py` keys on (`Slab`, `DeckSurface`, `Parapet_L/R`, `Pier2_pile3`, `Abut0_stem`, `Girder_5`, `Water`, ...).

## What to verify (acceptance criteria)

1. **Source → bridge.json.** Every number in `bridge.json` must be traceable to `report_text.txt` (NBI items 43/45/48/49/
   51/52/34, span table, element list, channel profile, photo captions). Flag anything that is not in the report or
   that contradicts it. `model_notes` are modelling assumptions read off the photos; they must be plausible, not exact.
2. **bridge.json → model.** `tools/verify_model.py --all` must report no FAIL. Tolerances are in the script
   (0.25 ft on widths, 0.5 ft on lengths, 1° on skew, exact counts for piles/columns/girders/supports).
3. **Model → photos.** Open `bridges/*/verification/compare_sheet.jpg` (or the per-view `compare_<view>.jpg`) and judge
   each pair against its `check` text in `pairs.json`: structure type, member counts and proportions, parapet shape,
   pier type, what is under the bridge, materials/colour, vegetation/season. Record findings per pair as
   PASS / MINOR / MAJOR with one line of reasoning.
4. **Deliverables present.** For every bridge: `renders/*.png` for all cameras in `BRIDGES[id]['cameras']`,
   `model/bridge_<id>.glb` (opens in a glTF viewer, node names preserved), `verification/dimension_report.md`.
5. **Code health.** `bridge_gen.py --build <id>` runs without errors for all three ids; no hard-coded numbers that
   duplicate `bridge.json` (the `BRIDGES` dict holds only modelling assumptions and must agree with the json).

## How to report

Write `bridges/<folder>/verification/REVIEW.md` (one per bridge) with: dimension table summary, per-photo-pair verdicts,
discrepancies found in `bridge.json` vs the report text, and concrete fix suggestions (file + function). Keep the
repository's English-only convention for code, comments and docs. Don't commit `blender/out/` (ignored).

## Fixing things

- Geometry/dimension bugs: `blender/bridge_gen.py` (`Frame`, `Ground`, `build_superstructure`, `build_substructure`,
  `build_site`), then rebuild + `verify_model.py --blend`.
- Material/lighting: `blender/common.py` (`standard_materials`, `setup_world`), textures via `blender/gen_textures.py`.
- Data errors: edit `bridges/<folder>/bridge.json` **and** the matching `BRIDGES` entry; both must agree.
- Keep every change rebuildable from scratch: no manual edits to .blend files.
